# DSH Science Review · 回答审查

在 DeepSeek Harness 的回答下方显示独立审查报告。审查员把回答中的主张与用户任务、工具执行记录和交付证据逐项对照。发现会同时列出回答原文、证据原文、来源、理由和修正建议。适用于 DSH Web，已适配 `0.2.2-rc.5`。

## 安装

### 从 DSH 插件页安装（推荐）

1. 在 DSH Desktop 或 Web 打开侧栏 **插件 → 添加插件**。
2. 输入 `dsh-science-review@0.3.0`，确认来源是 npm，点击 **安装**，完成后选择 **立即启用**。桌面版通过这个入口安装到当前桌面环境。
3. 打开 **设置 → 回答审查**，看到模型选择和核查预设即表示插件已加载。

本版支持的宿主版本是 `0.2.2-rc.5`。插件包内含编译好的网页界面。[DSH 官方插件管理说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/packages/client/ui-plugin-manager/README.zh.md)

### 从命令行安装（DSH Web）

在启动 Web 的同一套 DSH 环境中运行以下命令，再重新启动 Web。使用自定义 profile（保存插件和设置的独立环境）时，把 `web` 换成实际名称。

```sh
dsh plugin --profile web add dsh-science-review@0.3.0
```

### 从 GitHub 安装包或索引安装

- **安装包文件**。从 [GitHub Release](https://github.com/SPYfighting/dsh-science-review/releases/tag/v0.3.0) 下载 `dsh-science-review-0.3.0.tgz`。在文件所在目录运行 `dsh plugin --profile web add ./dsh-science-review-0.3.0.tgz`，然后重启 Web。
- **插件发现页**。在 **插件 → 实验性插件** 启用 **自定义插件索引**，打开 **发现 → 管理索引源 → 添加索引源**，粘贴下面的地址。搜索“回答审查”，核对版本后安装。[DSH 官方索引说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/docs/user/guide/plugin-market.zh.md)

```text
https://raw.githubusercontent.com/SPYfighting/dsh-science-review/main/index.json
```

## 开始使用

打开 **设置 → 回答审查**，选择审查模型及推理强度（effort）。模型来自 DSH 已配置的提供方，密钥由 DSH 管理。默认跟随目标回答所用的模型和强度。选定其他模型时，可以选它公布的强度或采用该模型默认值。

### 哪些轮次会审，审查什么

**主张**是能与要求、记录或成品对照的陈述。它可以是研究解释、一个日期、一项已经执行的操作，或对函数行为的承诺。**关键主张**看判断错误的后果：是否会改变主要结论、下一步行动、交付物能否使用，或是否越过用户授权。例如，把技术重复算成独立样本、把会议时间写错、承诺数据库写入失败时会回滚，都可能改变使用者的决定。

**关键轮次**决定何时发起审查。插件先在本地查找已完成回答里的可观察信号，如正式交付文件、工作区发生变更、给出关键数量或日程、提出明确决策、报告测试通过或失败、交付所要求的正文或代码。命中时，报告会写明触发缘由。这是可解释的中英文筛选规则，可能漏掉隐含结论；用户可以手动补审任一已完成回答。

| 设置 | 选项 |
| --- | --- |
| 触发时机 | **仅手动**（默认）、**关键轮次**、**每一轮** |
| 核查预设 | **高效**勾选数字与单位、执行记录、方法与结论。**全面**勾选下列九项。还可逐项调整，保存为自定义组合。 |
| 单轮覆盖度 | **关键主张**优先核对影响结果的内容；**全部可核查主张**要求逐段检查。报告显示模型实际申报的段落覆盖。 |
| 核查内容 | 数字与单位、执行记录、图表与数据、引文与文献标识、计划完成情况、方法与结论、代码关键节点、交付文本中的 AI 痕迹、任务范围与授权 |
| 补充标准 | 例如“报告显著性前先区分生物学重复与技术重复”。已保存的核查项选择继续生效，可自行勾选新增项目。 |

**代码关键节点**关注输入和输出约定、关键分支、异常路径、状态写入及对应测试。**交付文本中的 AI 痕迹**定位会影响读者理解或成品使用的具体文字，如通知里残留助手对话、论文对假想质疑的辩解、已有结果却仍写“待补充”。判断依据是文字和受众，无法据此认定作者身份。用户要求的模板留白、有依据的局限性属于合理表达。**任务范围与授权**会对照用户原话、已记录的许可及实际动作，区分“建议发送”“声称已发送”和“工具记录显示已发送”。

### 在会话中查看与处理

输入框旁的按钮直接用图标显示**当前有效模式**。放大镜表示仅手动，旗标表示关键轮次，叠页勾表示逐轮审查。鼠标悬停或使用读屏软件可读到模式名。点开按钮可切换本会话的模式，也可手动选择历史回答。

审查报告挂在原回答下方。收起时显示问题摘要，展开后优先列影响较大的三项，再按需展开其余发现。每项并列展示有问题的原文、对照证据、位置、判断依据和建议。明确冲突、待核实事项、局部提示分别展示。相同证据和设置的已完成报告可复用。

[查看会话按钮和报告示例](https://github.com/SPYfighting/dsh-science-review/tree/main/docs/界面)

有发现时，主助手会在**下一次用户发言**时收到审查意见。它应对照证据，更正成立的问题，或说明某条意见为何不适用。仅要求起草或说明时，修正也应遵守这个范围。想立即处理时，可点击 **起草复核请求**，编辑后自行发送。报告会显示意见送达进度；修正确实成立与否，应查看主助手回复或再次核对交付物。

### 如何控制 token 用量

日常工作可用 **关键轮次 + 关键主张 + 高效**。选择哪些轮次决定调用次数，未触发的轮次消耗零个审查 token。论文定稿、代码发布前可以手动对目标回答使用**全面**，并选择**全部可核查主张**。新安装默认仅手动触发、勾选全部九项。

一次审查会将已选核查项合并提交给模型。勾选范围会改变指令和发送的证据，例如开启代码检查才会加入符合条件的源码快照。输出篇幅、模型思考强度以及是否需要补审也影响总量。展开报告可看本次实际模型请求数，以及提供方返回的 token 总量。补审计入同一份报告；相同设置和证据命中已有报告时，重新查看不会产生新请求。

发布版用 `deepseek-flash / high` 在**全部可核查主张**下测了两组虚构任务，每个组合各一次，四次均直接得到报告。下表是提供方返回的总 token 数，含输入、缓存命中及输出。

| 同一份回答 | 高效 | 全面 |
| --- | ---: | ---: |
| 样本量与显著性 | 2,450 | 6,249 |
| 只起草通知、记录显示已发送 | 1,861 | 5,840 |

两例合计，高效用量低 64.3%。两种预设都发现了样本量和显著性错误。全面还标出了通知中的助手套话，并单列越权发送。高效也通过执行记录发现了发送问题，模型对相邻核查项的归类可能重叠。这个比例取决于输入和模型输出，不能作为固定折扣。[含开发期失败、重试和最终用量的实测记录](https://github.com/SPYfighting/dsh-science-review/blob/main/test/results/核查预设用量对照-2026-11-25.json)

## 本地开发与测试

项目测试环境使用 Node.js 24.9 或以上版本。DSH 的插件安装命令还需要可用的 pnpm。在此项目目录执行以下命令，可安装并启动一个独立的 Web 配置。

```sh
npm ci
npm run build
npm run dsh -- plugin --profile web add "link:$PWD"
npm run dsh -- web
```

项目启动器把测试配置、凭据和会话放在本目录的 `.dsh-dev/` 中。首次使用真实模型时，请在这个 DSH 界面的 **设置 → 模型** 中配置提供方。已有本地配置并已安装插件时，只需运行最后一行。

也可以从源码生成安装包，再装入自己的 DSH Web 配置。

```sh
npm pack
dsh plugin --profile web add "$PWD/dsh-science-review-0.3.0.tgz"
```

单元测试和真实宿主集成测试可分别运行。后者将插件安装到临时 DSH 配置，使用本机模拟模型制造样本量矛盾，验证手动请求、自动触发、原文定位、下一轮反馈和重启恢复，无需模型密钥。

```sh
npm test
npm run build
npm run test:integration
```

开发预览版 `dsh-review` 的用户可先执行 `dsh plugin --profile web remove dsh-review`，再安装新包并重启。若曾保存全局审查设置，在对应 profile 的 `cordis.patch.yml` 找到 `id: dsh-review` 那一条，将它的 `name` 改为 `dsh-science-review`，保留原来的 `id` 和 `config`。历史报告和会话模式沿用原有标识。

### 真实模型校准

2026-11-25 使用已登录的 DeepSeek 账号和 `deepseek-flash / high` 检查了五个虚构案例。模型区分了 6 个独立样本和 12 次测量、发现空数组返回 NaN，以及成稿缺少已知会议时间和超出起草授权的模拟发送。明确要求保留占位符的模板没有触发发现。初测中模型把论文里的防御性辩解判得过重；校准后复测将该句列为措辞提示，并保留了合理的样本量局限。完整过程共 7 次模型请求。

源项目的 `test/results/DeepSeek审查实测-2026-11-25.json` 保留每次的虚构输入、实际报告和模型用量。可在源项目中执行以下命令单独复测某个案例（会使用项目 DSH 的 DeepSeek 账号额度）。

```sh
node test/live-account.mjs --live --case=notice
node test/live-account.mjs --live --case=research,notice --presets=efficient,full
```

## 审查依据和边界

审查使用一次独立的 DSH 模型请求，必要时可再请求一次以纠正输出。审查员没有工具权限。主任务的工具返回、用户原话、待办记录、交付登记与助手自己的陈述带有不同来源标签。逐字引文由插件与本次输入校对，证据不匹配且无法纠正时显示失败。段落覆盖数反映模型自报的检查范围，不能作为科学正确率。

证据窗口以目标轮次为中心，并可选入此前最近三个已完成回答中的相关工具记录。对正式交付的 CSV、TSV、Markdown、JSON、纯文本，以及开启代码检查时支持的源代码文件，若 DSH 留有该轮的工作区快照，审查员还可引用文件名、结束版本的行号及原文。每次最多摘录四个文件。已修改文件只核对变更段及相邻文本。窗口过长、快照不可用或格式不支持时，报告会标明限制。

对论文、图像和计算结果的结论取决于现有证据。联网解析 DOI、重新运行分析，以及长任务执行中的定时检查点，目前均在实现范围之外。自动审查在主会话的一轮回答完成时触发。

审查会把所选证据发给设置中指定的模型提供方。报告保存在原会话历史内，沿用该历史的分享及日志上传设置。若开启 LiveShare，共享会话历史的获准访问者也可能读取报告。

**与 Claude Science 的对应关系。** 官方 Reviewer 会独立读取近期回答、批准的计划、产物和执行记录，在回答后及长任务检查点运行，也支持手动请求、消息下的发现卡片、自定义标准和主助手后续纠正。这里采用 DSH 的原生会话事件、模型目录和 Web 扩展接口实现相应交互。关键轮次筛选、段落覆盖和结构化报告校验是本插件的实现选择。[Anthropic Reviewer 文档](https://claude.com/docs/claude-science/the-reviewer)

**与其他 DSH 插件共存。** DSH 实验性 Auto review 评估待执行工具的权限。本插件使用独立的设置项、会话记录及界面入口。旧科研工作台的自动审查由 `DSH_SCIENCE_AUTO_REVIEW=1` 启用；若同时开启两套回答自动审查，同一轮可能产生两份报告。这里借鉴了旧工作台按轮核对数字、执行记录、图文及引用的思路。当前版本固定已验证的宿主版本，因为 DSH 将可忽略的插件会话记录接口标记为实验性。[DSH Auto review](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/packages/experimental/auto-review/README.md) · [DSH 会话记录接口](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/packages/core/session/src/index.ts#L479-L513) · [原科研工作台](https://github.com/SPYfighting/dsh-science-plugin/blob/cd38feebf9f86075e85f980a3e9e1ad2083cf5be/lib/reviewer.js)
